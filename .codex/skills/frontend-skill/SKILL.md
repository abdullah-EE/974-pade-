# Frontend Skill

Source inspiration: `openai/skills` curated `frontend-skill`.

Use this skill for visually strong app, prototype, and demo UI work where hierarchy, imagery, motion, and restraint matter more than adding more components.

## Working Model
- Start with a visual thesis, not a component checklist.
- Give each screen one dominant job and one obvious next action.
- Use imagery as product evidence, not decoration.
- Prefer strong sections, media, spacing, and contrast over generic card stacks.

## App UI Rules
- Organize around the primary workspace, navigation, secondary context, and one clear action accent.
- Cards should be used only when the card itself is the interaction.
- Avoid dashboard mosaics, repeated filler panels, random icons, weak contrast, and ornamental gradients.
- Text should be product UI copy: status, action, freshness, and decision value.

## Imagery
- The first screen needs a real visual anchor.
- Use in-situ photography for venues and sports products.
- Avoid fake placeholders, busy images behind text, and repeated visuals.
- If multiple venues exist, each should have a distinct image or distinct image treatment.

## Motion and Depth
- Motion must support hierarchy and affordance.
- Use visible but restrained entrance, press, modal, and carousel motion.
- Use depth through layered surfaces, shadows, scale, perspective, and image overlays.

## Rejection Test
Reject the work if it feels like generic stacked cards, has no strong visual anchor, repeats content, hides the primary action, or still works visually after removing all imagery.
